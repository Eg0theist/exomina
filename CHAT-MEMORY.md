# Whole-chat memory

This feature was inspired by [Victor Taelin's proposal for a chat that never ends](https://gist.github.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449): compress a conversation into a binary tree of short summaries, and let the model zoom back into the original messages whenever it needs the details. Exomina builds on that idea in its own way. Every conversation keeps its own tree, the memory carries across providers, it sits beside the shared notes instead of replacing them, and it adds credential redaction, known dates, background summaries on your existing subscriptions, and export.

Each conversation has an append-only source journal and a persistent binary tree of summaries. Short source records stay exact; longer records and pairs are summarized into entries of at most 512 UTF-8 bytes. Originals remain available through `conversation_zoom`; `conversation_date` returns known dates without inventing missing legacy timestamps. Attachments retain references; their pixels are read separately.

New user turns start fresh provider sessions with a chronological tree view. Within an active task, follow-ups can continue the session. The view compacts in batches from 128,000 toward 64,000 bytes; the summarizer’s view uses 32,000 toward 16,000. Available sibling pairs merge by normalized age from the last source in their range, with older ties first. Jobs and views persist across restarts. Pending summaries never stand in for facts: source tools remain available, and an oversized or failed view uses the existing recent-message fallback.

Background work uses an available, visible subscription or local model selected through Exomina’s existing verified-usage checks. It can use up to eight workers, with at most five attempts per oversized summary. It has no tools and cannot sign in, redeem resets or use a paid API connection automatically. Its context stops before the first unfinished earlier source. No polling keep-alive requests are sent. Stable prompt prefixes and four-line Anthropic blocks support caching where the provider supports it.

In **Settings → Memory and privacy**, **Remember the whole chat** controls capture and use. **Summarize in the background** controls model requests while retaining the captured originals. Historical chat text and sanitized tool results can be sent to the selected summarizer and use its allowance. Shared-note controls are separate. Deleting a conversation cancels its summary work and removes its journal.

The journal saves visible messages, narration, follow-ups and tool activity. It excludes hidden reasoning, binary payloads and sign-in/security tool exchanges, and redacts recognized credentials. Tool echoes retain at most 30,000 characters, preserving the beginning and end and marking the omitted middle; long prose is split without that clipping. Existing transcripts supply only the tool excerpts they already retained. Credential detection cannot recognize every arbitrary secret in prose; do not paste secrets into chats.

JSON and Markdown chat exports include the sanitized original journal and provenance, excluding derived summaries and runtime caches. Reimport creates searchable archive source records; it does not restore live chats or native sessions. The tree is local to this installation; existing conversation sync does not synchronize its raw tool journal or summary cache.

Verification covers tree persistence, merge ordering, bounded jobs, source retrieval, privacy filters, model failures, settings, deletion, export/import and prompt preservation.
